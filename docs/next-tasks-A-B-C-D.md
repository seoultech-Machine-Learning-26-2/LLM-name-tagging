# 다음 단계: 강의 기반 모델 비교와 결과 분석

> 상태: 팀 검토용 제안 · 작성: 정혜원/B/Codex · 최종 수정: 2026-11-11

## 1. 이번 단계의 목표

**같은 데이터에 강의에서 배운 분류 모델 4개를 적용하고, 성능 차이를 이론과 실제 결과로 설명한다.** 최고 정확도 달성보다 공정한 비교, 알고리즘 이해, 실패 원인 검증, 다른 환경에서의 재실행을 우선한다. 다만 공지의 완성도 평가에는 모델 성능도 포함되므로 낮은 점수를 설명만 하고 끝내지 않고, 원인 가설 하나를 실험으로 확인한다.

이 문서는 사용자가 제공한 과제 공지와 강의 PDF를 참고한 다음 작업 제안이다. PDF 속 실습 지시를 현재 저장소에서 실행하라는 요청으로 취급하지 않았다. 아래 역할·일정은 팀 합의 전 제안이며, 아직 실행한 실험이나 확정된 팀 결정이 아니다. 강의 PDF는 저장소에 복사하거나 업로드하지 않는다.

### 과제 요구사항과 연결

| 공지의 평가·제출 항목 | 우리 팀이 준비할 근거 |
| --- | --- |
| 문제 정의의 적절성·난이도 25점 | 처음 보는 질문의 응답에서 18개 작성 LLM을 구분하는 문제, 데이터 규모·주제 영향·동일 개발사 모델 간 유사성 설명 |
| 방법론의 적절성·이해도 40점 | 강의 모델 4개 이론, 전처리 이유, 조건 통제 실험, 오분류·과적합 분석 |
| 구현·성능·보고서 완성도 35점 | 실행 가능한 코드, 동일 평가 기준의 결과표, 한계와 결론, 재실행 검증 |
| 중간 발표 30% | 각자 자기 모델·코드·결과를 설명하고 질문에 답하는 연습; 높은 점수나 완성률 자체를 목표로 삼지 않음 |
| 최종 보고서 60% | Word 또는 한글 문서로 작성한 설명서를 PDF로 변환 |
| 동료 평가 10% | 담당 작업·커밋·분석·상호 검토 기록 |

위 25/40/35는 최종 보고서 평가의 세부 항목이며, 30%/60%/10%는 프로젝트 평가 구성이다. 서로 합산하지 않는다. 강의 1의 일반 성적 안내보다 이번에 제공된 팀프로젝트 공지를 이 계획의 기준으로 삼았다.

브랜치는 서로 다른 작업 이력을 보관하는 Git 작업 공간이다. 이 문서 작성 시 B 브랜치에는 A 데이터가 포함되지만 C의 코드는 아직 없다. **각자 모델을 만들기 전에 A/B/C 산출물을 팀 작업 기준 브랜치로 모으고 실행부터 확인한다.** C 코드를 새로 복제해 각자 다르게 고치지 않는다. 실제 위치는 현재 `evaluate.py`이며 첨부 자료의 `eval/evaluate.py` 안내와 다르다.

기존 계획의 Random Forest(A), SVM(B), Logistic Regression(D)은 유지하고, C의 필수 모델은 XGBoost 대신 **Decision Tree**로 바꾸는 것을 제안한다. 단일 트리와 랜덤 포레스트를 비교하면 강의의 분산·앙상블 효과를 직접 설명할 수 있다. XGBoost와 사전학습 언어모델 4종은 선택 확장으로 옮긴다. 이미 수행한 실험이 있다면 삭제하지 말고 추가 실험으로 보존한다.

## 3. A·B·C·D 담당표

| 담당 | 필수 모델 | 반드시 답할 질문 | 공통 업무 | 개인 보고서 |
| --- | --- | --- | --- | --- |
| A | Random Forest | 트리 수와 깊이 제한이 일반화에 어떤 영향을 주는가? 단일 트리보다 항상 좋은가? | 데이터 명세·출처 관리, C와 트리/숲 비교 | `docs/experiments/A-random-forest.md` |
| B — 정혜원 | Linear SVM | 문체만 쓸 때와 TF-IDF를 추가할 때 무엇이 달라지는가? | 공통 특징·입력 버전 관리 | `docs/experiments/B-svm.md` |
| C | Decision Tree | 깊은 트리가 train을 잘 맞혀도 val에서 낮아지는가? | 공통 평가·통합 결과표 관리 | `docs/experiments/C-decision-tree.md` |
| D | Logistic Regression / Softmax | 선형 경계와 규제가 이 데이터에 적절한가? 차원 축소가 어떤 정보를 잃는가? | PCA 비교, 보고서·발표 통합 | `docs/experiments/D-logistic-regression.md` |

위 보고서 경로는 앞으로 만들 파일이다. 통합 담당이 다른 사람의 이론·분석을 대신 쓰는 구조가 아니다. **각자 코드, 결과표, 그림, 이론 설명을 함께 제출**하고 D가 모아 편집한다.

### A: 랜덤 포레스트와 데이터 설명

1. **A-1 — 데이터 명세:** 데이터셋 원문 주소·다운로드 시점·사용 조건, 4개 컬럼의 뜻, 전체/분할별 개수, 결측·중복·질문 겹침 검사를 문서화한다. 강의 toy 데이터가 아니라 실제 LLM 응답 데이터라는 점과 일반화 범위를 설명한다. 개발사 매핑은 C의 정의와 맞춘다.
2. **A-2 — 공통 입력 실험:** 문체 32개로 `RandomForestClassifier`를 학습한다. 시작 설정은 `n_estimators=100`, `max_depth=None`, `min_samples_leaf=1`, seed 42. 이는 출발점이지 최적값이 아니다.
3. **A-3 — 조건 비교:** 먼저 깊이·잎 조건을 고정하고 트리 수 50/100/300을 비교한다. 다음으로 100개 트리에서 `max_depth` 5/10/None을 비교한다. 중복 설정을 재사용하면 5개 설정이다. 한 번에 여러 조건을 바꾸지 않는다.
4. **A-4 — 해석:** train/val BA, 학습 시간, seed별 변동, 상위 특징을 기록한다. C의 단일 트리와 같은 입력으로 비교한다. 중요도가 높은 특징이 원인이라고 단정하지 말고 길이와 단어 수처럼 상관된 특징의 중요도가 나뉠 수 있음을 설명한다. OOB 점수는 질문 단위 평가를 대신하지 못하므로 주 결과로 쓰지 않는다.

**완료 조건:** 원본 출처와 분할 검증 기록, 설정별 CSV, 비교 그림 1개 이상, 특징 중요도 그림, 단일 트리 대비 해석, 개인 보고서와 실행 명령.

### B: SVM과 특징 효과

1. **B-1 — 입력 고정:** 현재 문체 32개 중 9개가 상수라는 사실을 재확인하고 공통 입력 열 순서를 공유한다. 공통 비교에서는 32개를 유지하며, 별도 제거 실험을 한다면 train에서만 결정한다. 데이터 형식을 임의로 변경하지 않는다.
2. **B-2 — 공통 입력 실험:** train에서 학습한 스케일러와 `LinearSVC`를 연결하고 `C=0.1/1/10`을 비교한다. C는 오분류 허용과 경계 복잡도 사이의 균형을 조절하며, 값이 커질수록 일반적으로 규제가 약해진다.
3. **B-3 — 특징 비교:** 동일한 선형 SVM과 고정한 C로 `문체만 / 문자 TF-IDF만 / 결합`을 비교한다. 각 입력마다 C까지 다시 튜닝한 결과는 별도 표에 둬 특징 효과와 튜닝 효과를 구분한다.
4. **B-4 — 해석:** 왜 스케일링이 필요한지, 고차원 문자 특징이 주제 표현을 외울 수 있는지 설명한다. 입력별 혼동행렬·대표 오류 5개를 비교한다. 확률이 필요한 C 평가에는 train 내부 질문 그룹 분할로 보정한다. 보정 전 선형 SVM과 보정 후 결과를 구분한다.

**선택 확장:** 문체 입력에서만 RBF SVM을 선형 SVM과 비교한다. 먼저 C를 고정하고 gamma만 바꾸며 커널·계산량·과적합을 설명한다. 필수 실험을 끝낸 뒤 진행한다.

**완료 조건:** 문체 공통 비교 결과, 입력 3종 비교표, train/val 차이, 오류 5개 분석, 개인 보고서와 실행 명령.

### C: 결정트리와 공통 평가

1. **C-1 — 기준 정리:** 기존 `evaluate.py`와 결과 저장 형식을 공통 경로로 정리한다. 주 지표 BA, 보조 Accuracy·Macro F1을 함께 기록하도록 실험 표를 제공한다. D의 기존 템플릿과 모델 선택 기준이 다른 부분은 팀 확인 후 맞춘다.
2. **C-2 — 공통 입력 실험:** `DecisionTreeClassifier`에 문체 32개를 넣고 `max_depth=3/5/10/None`을 비교한다. `min_samples_leaf=1`을 고정하고 train/val 곡선을 그린다. 결정트리에는 스케일링이 필수가 아닌 이유를 설명한다.
3. **C-3 — 규제 비교:** 고정한 깊이에서 `min_samples_leaf=1/5/10`을 비교한다. 깊이 제한과 잎 크기 제한이 학습 데이터를 외우는 현상을 줄이는지 확인한다.
4. **C-4 — 해석·통합:** 상단 2~3단계만 트리를 그려 실제 분기 조건과 Gini 불순도를 설명한다. A와 단일 트리/숲의 성능·변동을 비교한다. 각 담당자가 작성한 오류 분석을 모아 공통 혼동 모델 쌍을 정리한다.

**선택 확장:** AdaBoost를 같은 문체 입력으로 추가해 순차적으로 오류를 보완하는 방식과 RF의 차이를 설명한다. XGBoost는 강의에서 직접 설명한 모델과 구분해 소개한다.

**완료 조건:** 공통 평가 안내, 깊이/잎 조건 비교표, train/val 곡선과 트리 그림, `results/course_comparison.csv`, 개인 보고서와 실행 명령.

### D: 로지스틱 회귀·차원 축소와 보고서 통합

1. **D-1 — 공통 입력 실험:** 스케일링한 문체 32개와 다중 클래스 `LogisticRegression`으로 `C=0.1/1/10`을 비교한다. 모델 이름에 회귀가 들어가도 이 문제에서는 분류기인 이유, softmax 확률·교차 엔트로피·규제 역할을 설명한다.
2. **D-2 — PCA 비교:** 같은 스케일링 문체 입력에서 `PCA 없음 / PCA 95% 설명분산 유지`를 고정한 로지스틱 회귀로 비교한다. PCA는 train에만 fit한다. 실제 선택된 차원 수, 설명분산 누적 곡선, val BA와 시간을 기록한다. 분산을 많이 보존해도 정답 구분에 중요한 정보가 보존된다고 보장되지 않는 이유를 논의한다.
3. **D-3 — 계수 해석:** 클래스별 계수 상위 특징을 확인한다. 스케일링과 상관 특징 때문에 계수 크기만으로 인과적 중요성을 말할 수 없다는 한계를 적는다. B의 문자 TF-IDF와 LR을 결합한 기존 기준선은 별도로 표기한다.
4. **D-4 — 통합:** 모든 개인 보고서를 공통 목차에 맞춰 모은다. 라이브러리 버전을 첫 문항에 두고 코드 실행 순서를 검증한다. 중간 발표용으로 각자 모델 설명과 예상 질문 3개씩을 모은다. 최종 문서는 Word/한글에서 작성 후 PDF로 변환한다.

**선택 확장:** PCA 2차원 그림과 K-Means 군집 분석. 군집 개수는 6/18 등을 실험하되 군집 번호가 정답 클래스 번호가 아님을 설명한다. Silhouette은 특징 공간에서의 군집 분리도이며 정답률이 아니다. 정답과의 관련성은 ARI/NMI 등 별도 지표로 살펴본다. 학습 때 정답을 넣지 않고 해석할 때만 모델·개발사·질문별 색을 비교한다. 두 차원 그림이 겹친다는 이유만으로 원래 고차원에서도 분류 불가능하다고 결론내리지 않는다.

**완료 조건:** LR 규제 비교표, PCA 전후 비교·설명분산 그림, 개인 보고서, 통합 보고서 틀과 실행 안내.

## 4. 전원 공통 실험 규칙

### 필수 실험과 비교 범위

- **실험 1:** 4개 모델 모두 같은 A 분할과 B 문체 32개로 비교한다. SVM/LR에는 train 기반 스케일링을 적용하며 RF/트리는 원시 값을 사용해도 된다. 이 차이를 표에 밝힌다.
- **실험 2:** 담당 모델에서 조건을 하나씩 바꾼 비교를 수행한다. A는 트리 수·깊이, B는 입력 특징, C는 깊이·잎 제한, D는 규제·PCA다. 조건을 통제한 결과와 각자 최적으로 튜닝한 결과를 섞지 않는다.
- **최소 기준선:** `DummyClassifier`로 클래스 사전확률 또는 최빈 클래스 기준을 기록하고 기존 TF-IDF+LR 기준선과 함께 둔다. 18개 균등 무작위의 기대 정확도 약 5.56%는 참고값이지 실제 실행 결과가 아니다.
- 고전 모델 4개와 PCA 비교가 필수다. 군집·AdaBoost·RBF·대형 언어모델은 선택이다. 모든 강의의 모든 알고리즘을 억지로 쓸 필요는 없다. 모델 이름을 연속 숫자로 바꾼 뒤 선형회귀/RMSE를 적용하지 않는다. 클래스 사이 숫자 거리는 의미가 없다.

### 학습·검증·최종 평가

1. `train` 1,889개로 학습하고 `val` 396개로 조건을 비교한다. `test` 414개는 최종 평가용으로 남긴다. 같은 질문은 분할 사이에 섞지 않는다.
2. 스케일러·TF-IDF·PCA·특징 선택은 train에서만 학습한다. train 내부 교차검증을 추가한다면 `GroupKFold` 등으로 `prompt_id`를 묶고 **각 fold 안에서 전처리부터 다시 학습**한다. 이미 전체 train에 fit한 행렬로 교차검증하면 검증 fold 정보가 반영될 수 있다.
3. 시작 seed는 42다. 설정 수는 담당자당 약 6~10개로 제한하고, 최종 후보는 가능하면 seed 42/43/44로 변동을 확인한다. 결정적 알고리즘에서 동일한 결과를 세 번 얻었다고 독립적인 검증 증거가 늘었다고 쓰지 않는다.
4. 모델 선택 주 기준은 val의 18개 모델 BA(클래스별 재현율 평균)로 통일하는 것을 제안한다. Accuracy와 Macro F1도 반드시 함께 보고한다. 작은 차이는 불확실성을 적고 더 단순한 모델을 선택할 수 있다. 기존 C의 동률 처리·시드 기준과 다르게 할 경우 팀 합의 후 기록한다.
5. 최종 평가 전에 각 모델의 특징·설정·seed·평가 대상 목록을 고정한다. **최고 모델 하나뿐 아니라 비교할 최종 모델 4개를 사전 고정하고 각각 test를 한 번 평가한다.** 여기서 한 번은 튜닝에 재사용하지 않는다는 뜻이다. 조건별 탐색 결과는 val 표에 남긴다.
6. C의 기존 기준과 맞춰 최종 모델도 train만으로 학습한다. train+val 재학습과 섞지 않는다. test를 확인한 뒤 설정을 바꾸거나 더 좋은 설정만 골라 보고하지 않는다. 기존 베이스라인 test가 공개돼 있다는 사실도 한계로 밝힌다.
7. 개발사 6개 지표도 C의 같은 변환으로 계산한다. 현재 코드는 모델 확률을 개발사별 합산한 `company_BA`와, 1위 모델의 개발사를 사용한 `company_BA_argmax`가 구분돼 있다. 표에 방식을 명시하고 서로 다른 방식의 숫자를 직접 비교하지 않는다.
8. 확률이 없는 LinearSVC는 train 내부에서 질문 단위 분할을 사용해 확률을 보정한다. 전처리도 보정 fold 안에서 fit한다. 보정 결과는 보정된 예측기로 보고하고, log loss에 결정 점수를 그대로 확률처럼 넣지 않는다. 구현이 지연되면 임의 softmax로 채우지 말고 확률 지표를 미측정으로 표시한 별도 표를 만든다.

유의미한 개선의 통계 판정은 선택 분석으로 둔다. 기존 C의 질문 단위 bootstrap을 사용하면 점수 차이의 불확실성을 설명할 수 있지만, 기준선보다 유의하게 높아야만 과제가 성공한 것으로 정의하지 않는다. 22개 val 질문이라는 작은 검증 규모도 결론에 반영한다.

## 5. 낮은 성능을 설명하는 방법

**관찰 → 가능한 원인 → 확인 실험 → 결과 → 남은 한계** 순으로 쓴다. “데이터가 적어서”, “모델이 단순해서”만으로 끝내지 않는다.

| 관찰 | 검증할 가설 | 실험·증거 | 주의할 해석 |
| --- | --- | --- | --- |
| train은 높고 val은 낮음 | 과적합: 학습 자료를 외워 새 질문에 약함 | 트리 깊이 제한·C 조정 전후의 train/val 차이 | 점수 하나만으로 원인 확정 금지 |
| train과 val이 모두 낮음 | 현재 특징이나 모델 표현력이 부족함 | 같은 모델에서 문체/TF-IDF 비교, 비선형 모델과 비교 | 최적화 실패·잘못된 라벨/행 순서도 먼저 검사 |
| 같은 개발사 모델끼리 혼동 | 세부 문체가 유사할 가능성 | 18개/6개 지표와 혼동행렬, 실제 오류 사례 | 학습 불균형·확률 합산 효과와 구분 |
| 형식 특징이 기여하지 않음 | 입력 파일에 형식 정보가 거의 없음 | B의 9개 상수 특징 확인 | 원래 응답에 Markdown이 없었다고 단정 금지 |
| TF-IDF를 추가해도 val이 낮음 | 주제 표현 의존 또는 고차원·표본 부족 | 단어 조각·오류 질문 확인, train 질문 수별 학습 곡선 | 관찰만으로 주제 의존이 입증됐다고 쓰지 않기 |
| PCA 후 성능 하락 | 분산이 작은 구별 정보가 사라짐 | PCA 전후 동일 분류기 비교, 유지 차원 수 기록 | 가능성으로 제시하고 실제 원인과 구분 |
| seed·질문별 편차가 큼 | 작은 데이터에서 결과가 불안정함 | seed별 결과, 질문 단위 신뢰구간 | 행 단위로 독립 표본인 것처럼 계산 금지 |

각자 val 오분류 5개 이상을 `id`, 질문, 실제/예측 모델, 관찰한 문체, 가설, 근거와 함께 정리한다. 사람도 구분하기 어려운 사례를 설명할 수 있지만, 임의로 정답을 바꾸지 않는다. 학습 곡선을 만든다면 train 질문을 25/50/75/105개처럼 묶어 늘리고 동일한 val을 쓴다. 이 수치는 예시이며 부분집합에 클래스가 모두 있는지 확인한다.
