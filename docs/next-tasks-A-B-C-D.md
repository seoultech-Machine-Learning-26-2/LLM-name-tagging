# 다음 단계: D의 모델 배정에 따른 구현·비교·결과 분석

> 상태: D 모델 배정 반영 · 일정은 팀 합의, 세부 실험은 제안 · 작성: 정혜원/B/Codex · 최종 수정: 2026-11-11

## 1. 이번 단계의 목표

**[D의 모델 설계](D-model-research-and-design.md)에 따라 각자 고전 모델 1개와 심화 모델·기법 1개를 구현하고, 성능 차이를 이론과 실제 결과로 설명한다.** 최고 정확도 달성보다 공정한 비교, 알고리즘 이해, 실패 원인 검증, 다른 환경에서의 재실행을 우선한다. 다만 공지의 완성도 평가에는 모델 성능도 포함되므로 낮은 점수를 설명만 하고 끝내지 않고, 원인 가설 하나를 실험으로 확인한다.

사용자 확인에 따라 D 문서의 번호 1~4를 A~D에 대응시켜 모델 배정을 유지한다. 아래 세부 실험 조건은 제안이고, 일정은 사용자가 전달한 팀 합의를 반영하며 실험 결과가 아니다. 앞선 버전의 C 결정트리 대체·심화 모델 선택 전환 제안은 철회한다. D 문서에 남은 그 제안에 대한 언급은 이전 계획의 이력으로 읽는다. 강의 PDF는 참고 자료이며 저장소에 복사하거나 업로드하지 않는다.

### 과제 요구사항과 연결

| 공지의 평가·제출 항목 | 우리 팀이 준비할 근거 |
| --- | --- |
| 문제 정의의 적절성·난이도 25점 | 처음 보는 질문의 응답에서 18개 작성 LLM을 구분하는 문제, 데이터 규모·주제 영향·동일 개발사 모델 간 유사성 설명 |
| 방법론의 적절성·이해도 40점 | 고전 모델·심화 기법의 이론, 강의 개념과 연결, 전처리 이유, 조건 통제 실험, 오분류·과적합 분석 |
| 구현·성능·보고서 완성도 35점 | 실행 가능한 코드, 동일 평가 기준의 결과표, 한계와 결론, 재실행 검증 |
| 중간 발표 30% | 각자 자기 모델·코드·결과를 설명하고 질문에 답하는 연습; 높은 점수나 완성률 자체를 목표로 삼지 않음 |
| 최종 보고서 60% | Word 또는 한글 문서로 작성한 설명서를 PDF로 변환 |
| 동료 평가 10% | 담당 작업·커밋·분석·상호 검토 기록 |

위 25/40/35는 최종 보고서 평가의 세부 항목이며, 30%/60%/10%는 프로젝트 평가 구성이다. 서로 합산하지 않는다. 강의 1의 일반 성적 안내보다 이번에 제공된 팀프로젝트 공지를 이 계획의 기준으로 삼았다.

브랜치는 서로 다른 작업 이력을 보관하는 Git 작업 공간이다. A 데이터와 B 특징은 main에 반영돼 있다. **각자 모델을 만들기 전에 main에 통합된 C 평가 코드로 실행부터 확인한다.** C 코드를 각자 다르게 복제하지 않는다. C 브랜치에는 `eval/evaluate.py`와 루트 `evaluate.py`가 모두 있으므로 사용할 파일과 버전을 고정한다.

고전 모델의 공통 문체 입력 비교 → 모델별 특징 확장 → 심화 모델의 기본형/기법 적용형 비교 순서로 진행한다. 결정트리는 트리 계열 이해를 돕는 선택 비교이며 C의 XGBoost를 대체하지 않는다. PCA·군집은 선택 분석으로 두고 D의 융합 모델을 우선한다.

위 보고서 경로는 앞으로 만들 파일이다. 통합 담당이 다른 사람의 이론·분석을 대신 쓰는 구조가 아니다. **각자 코드, 결과표, 그림, 이론 설명을 함께 제출**하고 D가 모아 편집한다.

### A: 랜덤 포레스트와 데이터 설명

1. **A-1 — 데이터 명세:** 데이터셋 원문 주소·다운로드 시점·사용 조건, 4개 컬럼의 뜻, 전체/분할별 개수, 결측·중복·질문 겹침 검사를 문서화한다. 강의 toy 데이터가 아니라 실제 LLM 응답 데이터라는 점과 일반화 범위를 설명한다. 개발사 매핑은 C의 정의와 맞춘다.
2. **A-2 — 공통 입력 실험:** 문체 32개로 `RandomForestClassifier`를 학습한다. 시작 설정은 `n_estimators=100`, `max_depth=None`, `min_samples_leaf=1`, seed 42. 이는 출발점이지 최적값이 아니다.
3. **A-3 — 조건 비교:** 먼저 깊이·잎 조건을 고정하고 트리 수 50/100/300을 비교한다. 다음으로 100개 트리에서 `max_depth` 5/10/None을 비교한다. 중복 설정을 재사용하면 5개 설정이다. 한 번에 여러 조건을 바꾸지 않는다.
4. **A-4 — 해석:** train/val BA, 학습 시간, seed별 변동, 상위 특징을 기록한다. C의 XGBoost와 같은 문체 입력으로 비교한다. 중요도가 높은 특징이 원인이라고 단정하지 말고 길이와 단어 수처럼 상관된 특징의 중요도가 나뉠 수 있음을 설명한다. OOB 점수는 질문 단위 평가를 대신하지 못하므로 주 결과로 쓰지 않는다.

**완료 조건:** 원본 출처와 분할 검증 기록, 설정별 CSV, 비교 그림 1개 이상, 특징 중요도 그림, RF 설정별 해석, 개인 보고서와 실행 명령.

### B: SVM과 특징 효과

1. **B-1 — 입력 고정:** 현재 문체 32개 중 9개가 상수라는 사실을 재확인하고 공통 입력 열 순서를 공유한다. 공통 비교에서는 32개를 유지하며, 별도 제거 실험을 한다면 train에서만 결정한다. 데이터 형식을 임의로 변경하지 않는다.
2. **B-2 — 공통 입력 실험:** train에서 학습한 스케일러와 `LinearSVC`를 연결하고 `C=0.1/1/10`을 비교한다. C는 오분류 허용과 경계 복잡도 사이의 균형을 조절하며, 값이 커질수록 일반적으로 규제가 약해진다.
3. **B-3 — 특징 비교:** 동일한 선형 SVM과 고정한 C로 `문체만 / 문자 TF-IDF만 / 결합`을 비교한다. 각 입력마다 C까지 다시 튜닝한 결과는 별도 표에 둬 특징 효과와 튜닝 효과를 구분한다.
4. **B-4 — 해석:** 왜 스케일링이 필요한지, 고차원 문자 특징이 주제 표현을 외울 수 있는지 설명한다. 입력별 혼동행렬·대표 오류 5개를 비교한다. 확률이 필요한 C 평가에는 train 내부 질문 그룹 분할로 보정한다. 보정 전 선형 SVM과 보정 후 결과를 구분한다.

**선택 확장:** 아래 ModernBERT 담당 작업을 마친 뒤 문체 입력에서만 RBF SVM을 선형 SVM과 비교한다. 먼저 C를 고정하고 gamma만 바꾸며 커널·계산량·과적합을 설명한다. 필수 실험을 끝낸 뒤 진행한다.

**완료 조건:** 문체 공통 비교 결과, 입력 3종 비교표, train/val 차이, 오류 5개 분석, 개인 보고서와 실행 명령.

### C: XGBoost·Qwen LoRA와 공통 평가

1. **C-1 — 기준 정리:** 현재 main에 통합된 평가 코드 중 사용할 파일·버전을 고정한다. BA·Accuracy·Macro F1, 개발사 평가 방식과 예측 확률 열 순서를 공유한다. D 템플릿과 모델 선택 기준 차이는 팀 확인 후 맞춘다.
2. **C-2 — XGBoost 공통 입력:** 문체 32개로 다중 클래스 분류를 구현한다. 깊이 3/6, 학습률 0.05/0.1처럼 작은 범위에서 비교하고 나머지 조건은 고정한다. 조기 종료는 val만 사용하며 선택된 트리 수를 기록한다. 설정은 시작 제안이며 최적값이 아니다.
3. **C-3 — 특징 조합:** 길이·문장부호 등 기존 특징의 조합을 추가해 공통 입력과 비교한다. train에서 정의한 변환만 적용하고, 깊이·학습률까지 동시에 바꾼 효과와 구분한다. RF와 비교하며 배깅과 순차 부스팅의 차이를 설명한다.
4. **C-4 — Qwen LoRA:** D가 정한 0.8B 모델의 실제 저장소·체크포인트·라이선스·분류 지원·GPU 메모리를 확인하고 고정한다. 18개 분류 확률을 직접 출력하고 생성 문장 파싱으로 정답을 만들지 않는다. 동결한 본체+분류 헤드와 LoRA+같은 헤드를 같은 조건에서 비교해 추가 학습 효과를 설명한다. 시간·메모리·학습 파라미터 수를 기록한다.
5. **C-5 — 해석·통합:** XGBoost의 train/val 차이, 중요도와 오류 5개를 분석하고 Qwen 결과와 입력·학습 방식 차이를 설명한다. 담당별 결과를 통합한다. 2B는 0.8B와 같은 분할·seed·입력 길이·학습 예산으로 비교할 수 있을 때만 선택 실행한다.

**완료 조건:** XGBoost 공통/확장 특징 비교, Qwen 0.8B LoRA 비교, 시간·메모리 기록, 통합 평가표, 두 개인 보고서와 실행 명령. 자원 부족이나 모델 가용성 문제는 실패 로그와 시도·제약을 기록하고 대체·축소 범위를 팀과 확인한다.

### D: 로지스틱 회귀·의미/문체 융합과 보고서 통합

1. **D-1 — 공통 입력:** 스케일링 문체 32개와 다중 클래스 Logistic Regression으로 C=0.1/1/10을 비교한다. softmax·교차 엔트로피·규제와 계수를 설명한다.
2. **D-2 — 특징 확장:** 동일 LR 설정에서 문체만/TF-IDF만/결합을 비교한다. 이미 있는 C의 문자 TF-IDF+LR 기준선과 설정이 같은지 밝힌다. 기존 기준선을 새 실험으로 중복 보고하지 않는다.
3. **D-3 — 융합 구현:** Sentence-BERT 체크포인트·버전·입력 길이를 고정하고 의미 임베딩과 train 기반 스케일링 문체 특징을 연결해 MLP 분류기를 만든다. 임베딩 모델은 우선 동결하고, 미세조정을 한다면 별도 실험으로 기록한다.
4. **D-4 — 기여 분리:** 의미만/문체만/융합의 세 모델을 같은 분할·seed·학습 예산으로 비교한다. 각 분기의 용량 차이도 적는다. 융합이 나빠져도 결과를 보존하고 주제 의존·특징 크기·과적합 가능성을 오류 사례로 검토한다.
5. **D-5 — 통합:** 각자의 모델 원리·비교표·오류 분석을 모은다. 환경·라이브러리 버전을 첫 문항에 쓰고 실행 순서를 검증한다. 각자 예상 질문 3개를 준비하며 최종 문서는 Word/한글에서 PDF로 변환한다.

**선택 확장:** PCA·군집 시각화는 융합 실험 이후 진행한다. 2차원에서 겹친다는 이유로 원래 공간에서도 분류가 불가능하다고 단정하지 않는다. 군집 번호와 정답 번호를 직접 비교하지 않는다.

**완료 조건:** LR 규제·특징 비교, 의미/문체/융합 비교표, 오류 5개, 두 개인 보고서, 통합 보고서 틀과 실행 안내.

### A·B의 심화 모델 작업

- **A-5 — DeBERTa 기본형:** 체크포인트·입력 길이·분류 헤드를 고정하고 작성 모델 18개를 예측하는 기본 분류기를 학습한다. RF와 입력 정보·모델 크기가 다르므로 알고리즘만의 효과라고 해석하지 않는다.
- **A-6 — 주제 적대 학습:** 같은 기본형에 주제 예측 분기와 역방향 학습 신호를 추가한다. C 제안대로 train의 prompt_id를 주제 대용 라벨로 사용할 수 있으나 실제 의미 주제와 같지 않음을 명시한다. 강도 0과 작은 양수 조건을 비교하며 작성자 BA와 주제 예측 능력을 함께 본다. 주제 probe는 train 내부의 같은 질문 응답을 양쪽에 나눈 별도 진단이며, 작성자 최종 평가의 질문 분리를 변경하지 않는다. 처음 보는 val 질문 ID를 train 주제 분류기의 정답으로 평가하지 않는다.
- **B-5 — ModernBERT 기본형:** 동일한 전처리·입력 길이·분류 헤드로 대조 학습 없는 기본 분류기를 준비한다.
- **B-6 — 대조 학습:** 같은 작성 모델의 응답이 배치 안에 둘 이상 있도록 구성하고, 분류 손실만/분류+대조 손실을 비교한다. 다른 질문의 같은 작성자 응답을 양성 쌍으로 포함해 질문 의존을 줄이도록 구성한다. 18개 확률·BA·형제 정확도와 val 임베딩 Silhouette을 기록한다. 임베딩 분리도가 올라도 BA가 그대로면 분류 개선이라고 쓰지 않는다.

**A·B 추가 완료 조건:** 기본형/기법 적용형의 통제 비교, 목적함수·가중치·배치 구성 설명, 시간·메모리, 실패·오류 분석, 심화 모델 개인 보고서. 주제 예측·대조 학습의 원리와 강의의 일반화·손실 최소화 개념을 연결한다.

심화 실행 전 체크포인트·버전·라이선스·필요 GPU를 확인해 기록한다. 이 계획 수정은 다운로드·학습·유료 API 실행을 수행한 것이 아니다. 유료 서비스 사용이 필요하면 비용을 확인하고 별도 승인받는다.

## 4. 전원 공통 실험 규칙

### 필수 실험과 비교 범위

- **실험 1:** 4개 모델 모두 같은 A 분할과 B 문체 32개로 비교한다. SVM/LR에는 train 기반 스케일링을 적용하며 RF/XGBoost는 원시 값을 사용해도 된다. 이 차이를 표에 밝힌다.
- **실험 2:** 담당 모델에서 조건을 하나씩 바꾼 비교를 수행한다. A는 트리 수·깊이, B는 입력 특징, C는 부스팅 설정·특징 조합, D는 규제·특징 결합이다. 이후 각자 심화 모델의 기본형과 기법 적용형을 통제 비교한다. 조건을 통제한 결과와 각자 최적으로 튜닝한 결과를 섞지 않는다.
- **최소 기준선:** `DummyClassifier`로 클래스 사전확률 또는 최빈 클래스 기준을 기록하고 기존 TF-IDF+LR 기준선과 함께 둔다. 18개 균등 무작위의 기대 정확도 약 5.56%는 참고값이지 실제 실행 결과가 아니다.
- D가 정한 고전 모델 4개와 심화 모델·기법 4개를 담당 작업으로 유지한다. Qwen 2B·PCA·군집·결정트리 추가 비교·RBF는 선택이다. 심화 작업은 먼저 작은 실행으로 자원·가용성을 확인하고 불가능한 부분은 팀과 범위를 조정한다. 모든 강의의 모든 알고리즘을 억지로 쓸 필요는 없다. 모델 이름을 연속 숫자로 바꾼 뒤 선형회귀/RMSE를 적용하지 않는다. 클래스 사이 숫자 거리는 의미가 없다.

### 학습·검증·최종 평가

1. `train` 1,889개로 학습하고 `val` 396개로 조건을 비교한다. `test` 414개는 최종 평가용으로 남긴다. 같은 질문은 분할 사이에 섞지 않는다.
2. 스케일러·TF-IDF·PCA·특징 선택은 train에서만 학습한다. train 내부 교차검증을 추가한다면 `GroupKFold` 등으로 `prompt_id`를 묶고 **각 fold 안에서 전처리부터 다시 학습**한다. 이미 전체 train에 fit한 행렬로 교차검증하면 검증 fold 정보가 반영될 수 있다.
3. 시작 seed는 42다. 설정 수는 담당자당 약 6~10개로 제한하고, 최종 후보는 가능하면 seed 42/43/44로 변동을 확인한다. 결정적 알고리즘에서 동일한 결과를 세 번 얻었다고 독립적인 검증 증거가 늘었다고 쓰지 않는다.
4. 모델 선택 주 기준은 val의 18개 모델 BA(클래스별 재현율 평균)로 통일하는 것을 제안한다. Accuracy와 Macro F1도 반드시 함께 보고한다. 작은 차이는 불확실성을 적고 더 단순한 모델을 선택할 수 있다. 기존 C의 동률 처리·시드 기준과 다르게 할 경우 팀 합의 후 기록한다.
5. 최종 평가 전에 각 모델의 특징·설정·seed·평가 대상 목록을 고정한다. **최고 모델 하나뿐 아니라 고전·심화 및 기본형/적용형 중 비교할 최종 모델 목록을 사전 고정하고 각각 test를 한 번 평가한다.** 여기서 한 번은 튜닝에 재사용하지 않는다는 뜻이다. 조건별 탐색 결과는 val 표에 남긴다.
6. C의 기존 기준과 맞춰 최종 모델도 train만으로 학습한다. train+val 재학습과 섞지 않는다. test를 확인한 뒤 설정을 바꾸거나 더 좋은 설정만 골라 보고하지 않는다. 기존 베이스라인 test가 공개돼 있다는 사실도 한계로 밝힌다.
7. 개발사 6개 지표도 C의 같은 변환으로 계산한다. 현재 코드는 모델 확률을 개발사별 합산한 `company_BA`와, 1위 모델의 개발사를 사용한 `company_BA_argmax`가 구분돼 있다. 표에 방식을 명시하고 서로 다른 방식의 숫자를 직접 비교하지 않는다.
8. 확률이 없는 LinearSVC는 train 내부에서 질문 단위 분할을 사용해 확률을 보정한다. 전처리도 보정 fold 안에서 fit한다. 보정 결과는 보정된 예측기로 보고하고, log loss에 결정 점수를 그대로 확률처럼 넣지 않는다. 구현이 지연되면 임의 softmax로 채우지 말고 확률 지표를 미측정으로 표시한 별도 표를 만든다.

유의미한 개선의 통계 판정은 선택 분석으로 둔다. 기존 C의 질문 단위 bootstrap을 사용하면 점수 차이의 불확실성을 설명할 수 있지만, 기준선보다 유의하게 높아야만 과제가 성공한 것으로 정의하지 않는다. 22개 val 질문이라는 작은 검증 규모도 결론에 반영한다.

## 5. 낮은 성능을 설명하는 방법

**관찰 → 가능한 원인 → 확인 실험 → 결과 → 남은 한계** 순으로 쓴다. “데이터가 적어서”, “모델이 단순해서”만으로 끝내지 않는다.

| 관찰 | 검증할 가설 | 실험·증거 | 주의할 해석 |
| --- | --- | --- | --- |
| train은 높고 val은 낮음 | 과적합: 학습 자료를 외워 새 질문에 약함 | 트리 깊이 제한·C 조정 전후의 train/val 차이 | 점수 하나만으로 원인 확정 금지 |
| train과 val이 모두 낮음 | 현재 특징이나 모델 표현력이 부족함 | 같은 모델에서 문체/TF-IDF 비교, 비선형 모델과 비교 | 최적화 실패·잘못된 라벨/행 순서도 먼저 검사 |
| 같은 개발사 모델끼리 혼동 | 세부 문체가 유사할 가능성 | 18개/6개 지표와 혼동행렬, 실제 오류 사례 | 학습 불균형·확률 합산 효과와 구분 |
| 형식 특징이 기여하지 않음 | 입력 파일에 형식 정보가 거의 없음 | B의 9개 상수 특징 확인 | 원래 응답에 Markdown이 없었다고 단정 금지 |
| TF-IDF를 추가해도 val이 낮음 | 주제 표현 의존 또는 고차원·표본 부족 | 단어 조각·오류 질문 확인, train 질문 수별 학습 곡선 | 관찰만으로 주제 의존이 입증됐다고 쓰지 않기 |
| PCA 후 성능 하락 | 분산이 작은 구별 정보가 사라짐 | PCA 전후 동일 분류기 비교, 유지 차원 수 기록 | 가능성으로 제시하고 실제 원인과 구분 |
| seed·질문별 편차가 큼 | 작은 데이터에서 결과가 불안정함 | seed별 결과, 질문 단위 신뢰구간 | 행 단위로 독립 표본인 것처럼 계산 금지 |

각자 val 오분류 5개 이상을 `id`, 질문, 실제/예측 모델, 관찰한 문체, 가설, 근거와 함께 정리한다. 사람도 구분하기 어려운 사례를 설명할 수 있지만, 임의로 정답을 바꾸지 않는다. 학습 곡선을 만든다면 train 질문을 25/50/75/105개처럼 묶어 늘리고 동일한 val을 쓴다. 이 수치는 예시이며 부분집합에 클래스가 모두 있는지 확인한다.
