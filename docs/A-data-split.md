# [A] 데이터 분할 및 관리

> 상태: 기존 작업 완료 · 담당: 은진 좌(A) · 문서 이관: 2026-11-11 · B/Codex

## 1. 완료한 일

- 데이터 구조·결측치·중복·모델별 개수를 확인했다.
- 같은 질문의 응답이 서로 다른 분할에 섞이지 않도록 `prompt_id` 단위로 나눴다.
- seed 42로 Train/Validation/Test 분할 코드를 작성했다.
- 분할 CSV 3개와 공통 숫자 라벨 파일을 GitHub에 올렸다.

원래 노션 기록의 상태는 **진행 완료**다. 이 문서는 앞서 이 대화에서 읽은 노션 내보내기 내용과 GitHub `feature/data-split`의 산출물을 바탕으로 정리했다. 문서 이관 시 현재 CSV의 개수·결측·중복·질문 겹침을 다시 검사했다. 데이터 재분할이나 수정은 하지 않았다.

## 2. 데이터 이해

목표는 LLM 응답의 특징을 사용해 작성 모델 18종을 구분하는 다중 클래스 분류다. 개발사 단위로는 6개다.

| 항목 | 내용 |
| --- | --- |
| 전체 응답 | 2,699개 |
| 질문 | 150개 |
| 작성 모델 | 18개 |
| 모델별 응답 | 17개 모델 각 150개, `claude-fable-5` 149개 |
| 질문별 응답 | 149개 질문 각 18개, 나머지 1개 질문 17개 |

| 컬럼 | 의미 | 사용 |
| --- | --- | --- |
| `id` | 응답 식별자 | 예측 결과와 원본 행 연결 |
| `prompt_id` | 질문 식별자 | 그룹 분할·누수 검사 |
| `text` | 생성 응답 원문 | 입력 특징 추출 |
| `model` | 작성 모델 이름 | 정답 라벨; 입력에서 제외 |

같은 `prompt_id`가 여러 행에 등장하는 것은 정상 구조다. 같은 질문에 여러 모델이 응답했기 때문이다.

## 3. 데이터 품질 검사

| 항목 | 결과 |
| --- | --- |
| 필수 값 결측 | 0개 |
| 완전 중복 행 | 원래 A 기록: 0개 |
| 중복 `id` | 0개 |
| 중복 `text` | 0개 |
| 행 삭제 | 없음 |

모델별 표본 수는 거의 같아 18개 클래스의 불균형은 작다. 개발사는 보유 모델 수가 달라 응답 수가 다르므로 개발사 평가에는 별도 고려가 필요하다.

## 4. 분할 방법과 결과

질문 ID를 정렬한 후 seed 42로 70%/30%를 나누고, 남은 30%를 절반으로 나눴다. 행이 아니라 질문을 나누므로 실제 행 비율은 목표 비율과 조금 다르다.

| 분할 | 질문 수 | 응답 수 | 전체 대비 응답 비율 | 클래스 수 |
| --- | ---: | ---: | ---: | ---: |
| Train | 105 | 1,889 | 70.0% | 18 |
| Validation | 22 | 396 | 14.7% | 18 |
| Test | 23 | 414 | 15.3% | 18 |
| 합계 | 150 | 2,699 | 100% | 18 |

train/val, train/test, val/test 간 질문 ID 겹침은 모두 0개이며, 응답 ID도 중복되지 않는다. 질문별 응답을 함께 이동시켜 본 적 있는 질문의 표현 때문에 성능이 높아지는 데이터 누수 위험을 줄였다. 새로운 질문에 대한 일반화 성능을 평가하려는 목적이다.

| 개발사 | 모델 수 | Train | Val | Test |
| --- | ---: | ---: | ---: | ---: |
| Anthropic | 5 | 524 | 110 | 115 |
| OpenAI | 5 | 525 | 110 | 115 |
| Google | 4 | 420 | 88 | 92 |
| ZAI | 2 | 210 | 44 | 46 |
| Moonshot | 1 | 105 | 22 | 23 |
| Qwen | 1 | 105 | 22 | 23 |

## 5. 산출물과 사용 방법

| 파일 | 용도 |
| --- | --- |
| [split_data.py](../split_data.py) | 품질 검사와 분할 재현 |
| [원본 CSV](../data/train.csv) | 분할 전 원본 |
| [train.csv](../data/split/train.csv) | 학습·전처리 기준 계산 |
| [val.csv](../data/split/val.csv) | 설정 비교·모델 선택 |
| [test.csv](../data/split/test.csv) | 설정 고정 뒤 최종 평가 |
| [label_map.json](../data/split/label_map.json) | 모델 이름→숫자, 알파벳순 0~17 |

이미 분할된 CSV를 그대로 사용한다. 재현 확인이 필요할 때 저장소 최상위에서 `python split_data.py`를 실행할 수 있으며, 이 명령은 `data/split/` 파일을 다시 쓴다. 실행에는 NumPy·pandas·scikit-learn이 필요하다.

TF-IDF·스케일러·PCA는 train에만 fit하고 val/test에는 transform만 적용한다. 모델별로 임의 재분할하거나 `id`·`prompt_id`·`model`을 입력 특징으로 넣지 않는다. 6개 개발사 평가는 C의 공통 매핑과 평가 방식을 따른다.
