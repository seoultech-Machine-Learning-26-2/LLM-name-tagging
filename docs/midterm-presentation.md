## ⑥ ⭐ 핵심 발견: 질문 중심화 · `60초`

**🖥️ 화면**

### 같은 질문의 공통 특징을 보정하면 작성 모델을 더 잘 구분할 수 있을까?

### 질문 중심화 (Question Centering)

1. 같은 `prompt_id`에 속한 응답을 묶음
2. 응답들의 특징 벡터 또는 임베딩 평균 계산
3. 각 응답에서 질문별 평균을 빼서 공통 성분을 보정
4. 보정 벡터를 단독으로 사용하거나 원본 벡터와 결합

**핵심 결과: 7개 모델에서 val 성능 개선 관찰**

**🖼️ 그림**

- 모델별 **질문 중심화 전·후 BA 막대그래프**
- 발표에서는 개선 효과가 여러 모델에서 확인되었다는 점 강조

| 담당 | 모델 | 중심화 전 BA | 중심화 후 BA | 개선폭 | 검증 근거 |
|:---:|---|:---:|:---:|:---:|---|
| A | DeBERTa | 0.306 | **0.409** | 🔼 +10.5%p | paired bootstrap CI [5.6, 14.9] |
| B | Linear SVM | 0.301 | **0.386** | 🔼 +8.6%p | paired bootstrap CI [4.8, 12.9] |
| B | ModernBERT | 0.346 | **0.380** | 🔼 +3.4%p | paired bootstrap CI [0.3, 6.2] |
| C | XGBoost | 0.258 | **0.381** | 🔼 +12.3%p | 질문 단위 5-fold: 0.294 → 0.344 |
| C | Qwen LoRA | 0.328 | **0.482** | 🔼 +15.4%p | Q2 → Q3, seed 42 |
| D | Logistic Regression | 0.338 | **0.408** | 🔼 +7.0%p | D 담당자 수정값, CI [2.8, 11.4] |
| D | SBERT 융합 | 0.248 | **0.353** | 🔼 +10.5%p | seed 3개 평균 |

> [!IMPORTANT]
> ### 수치 해석 시 주의
>
> - 모든 값은 **val 18개 모델 BA** 기준입니다.
> - 서로 다른 모델을 같은 학습 조건으로 비교한 순위표가 아닙니다.
> - DeBERTa·SVM·ModernBERT의 개선폭은 각 보고서의 **paired bootstrap 비교값**으로 표시했습니다. 반올림된 BA 두 값의 단순 차이와 조금 다를 수 있습니다.
> - **SBERT 융합:** `0.2475 → 0.3527`은 seed 3개 평균으로 **+10.5%p**입니다. 별도로 seed 42 paired bootstrap에서는 **+12.5%p, CI [8.6, 16.4]**가 확인됐습니다.
> - **LR:** D 담당자가 지정한 수정 수치인 **0.338 → 0.408, +7.0%p, CI [2.8, 11.4]**를 사용합니다. 기존 원본 실험의 선택 설정 간 비교에서는 정규화 파라미터 `C`도 달랐으므로 개선폭을 중심화만의 순수한 효과로 단정하지 않습니다.
> - **DeBERTa·ModernBERT:** 질문 배치 방식만 변경한 대조군과 중심화 모델을 비교했습니다.
> - **Qwen:** Q2와 Q3는 질문 묶음 입력 여부도 달라, 개선폭 전부를 중심화 연산 하나의 순수한 효과라고 단정하지 않습니다.
> - **RF는 질문 중심화를 적용하지 않아 표에서 제외했습니다.**
> - 질문 중심화는 **같은 질문의 여러 응답을 함께 사용할 수 있는 조건**에서만 적용됩니다.

### 추가 검증

- XGBoost: 질문 단위 5-fold에서 **0.294 → 0.344**
- ModernBERT: 질문 배치 대조군 대비 개선 신뢰구간이 0보다 큼
- DeBERTa: 질문 배치 대조군 대비 개선 신뢰구간이 0보다 큼
- LR: 비교 조건에 따라 `C`가 달라질 수 있으므로 해석 시 주의
- SBERT 융합: seed 42 paired bootstrap에서 개선 확인

> [!TIP]
> **🎙️ 말할 것**
>
> **배경:** 같은 질문에 대한 여러 LLM의 답변이 존재함
>
> **방법:** 같은 질문 응답들의 공통 성분을 보정해 작성 모델의 차이를 강조함
>
> **결과:** 서로 다른 7개 모델에서 검증 성능 개선을 관찰함
>
> **한계:** 여러 응답을 함께 이용해야 하며, 모델별 학습·입력 조건은 다름
>
> **핵심 문장**
>
> "같은 질문의 응답 묶음을 사용할 수 있는 조건에서, 질문 중심화를 적용한 7개 모델 모두 검증 성능이 향상됐습니다."

## ⑦ 고전 모델 · `35초`

**🖥️ 화면**

### 모델별 실험 결과

| 모델 | val BA | 실험에서 확인한 점 |
|---|:---:|---|
| Random Forest | 0.205 | 트리 수·깊이를 바꾼 설정 간 차이가 seed 변동 범위와 비슷 |
| Linear SVM | **0.386** | 문체 특징 스케일링과 질문 중심화가 성능에 영향 |
| XGBoost | **0.381** | 깊은 트리의 과적합 확인 후 깊이 3·규제 설정 채택 |
| Logistic Regression | **0.408** | TF-IDF·문체 특징 결합과 질문 중심화에 따른 성능 개선 관찰 |

### 주요 관찰

**Random Forest**
- 중심화 미적용
- val BA 약 0.205
- 트리 수·깊이에 따른 차이는 seed 변동보다 크지 않음

**Linear SVM**
- 스케일링 제거 시 문체 모델 BA **0.278 → 0.230**
- 질문 중심화 결합 모델 BA **0.386**

**XGBoost**
- 깊이 6에서 train BA **0.94~0.96**으로 과적합 관찰
- 깊이 3·규제 적용 후 특징 추가와 질문 중심화 진행
- 최종 val BA **0.381**

**Logistic Regression**
- TF-IDF와 문체 특징을 결합한 입력 사용
- 질문 중심화 적용 후 발표 기준 val BA **0.408**
- 담당자 수정 기준 개선폭 **+7.0%p**
- TF-IDF 30,000 → 5,000차원 실험에서 약 **+3.3%p** 개선 관찰
- 단, 차원 수 실험에서도 최적 `C`가 달라 차원 축소만의 효과로 단정하지 않음

> [!NOTE]
> **LR 실험 조건 주의**
>
> 기존 원본 실험의 선택 설정을 비교할 때 정규화 파라미터 `C`가 동일하지 않았습니다. 따라서 실험 간 차이를 특정 기법 하나의 효과로 해석할 때 주의해야 합니다.
>
> 발표 수치는 D 담당자가 지정한 **val BA 0.408**로 통일합니다.

> [!TIP]

### 실험 전 가설과 검증 결과

| 기법 | 가설 | 실제 val 결과 | 판단 |

### 현재 실험의 주요 한계

**① 작은 검증 데이터**
- Validation: 22문항, 396개 응답
- 약 1~3%p 차이의 해석에 주의 필요

**② 과적합**
- 일부 모델은 train BA 약 **0.98~1.00**
- 반면 val BA는 약 **0.4~0.5** 수준

**③ 질문 중심화 적용 조건**
- 같은 질문의 다른 응답이 함께 필요
- 응답 하나만 독립적으로 분류하는 조건과 구분해야 함

**④ 모델별 실험 조건 차이**
- seed 수, epoch 선택 방식, 입력 특징, 확률 보정 방식이 다름
- 일부 실험에서는 비교 조건의 하이퍼파라미터가 동일하지 않음
- 따라서 모델 간 성능 차이를 특정 기법 하나의 효과로 해석하기 어려움

**⑤ Validation 기반 설정 선택**
- 여러 설정을 val로 탐색하므로 val 결과가 다소 낙관적일 수 있음

> [!TIP]
> **🎙️ 말할 것**
>
> "검증 질문 수가 적고 일부 모델에서 과적합이 확인됐습니다. 또한 질문 중심화는 여러 응답을 함께 이용하는 조건에서만 가능하므로, 결과를 해석할 때 이 제약을 고려해야 합니다."

**🖥️ 화면**

### 서로 다르게 틀리는 모델을 결합하면 성능을 더 높일 수 있을까?

**현재까지의 결과**

### 향후 팀 통합 앙상블 검토

| 개선 방향 | 방법 | 목적 |
|---|---|---|
| **① 모델 결합** | Qwen·DeBERTa·ModernBERT 등 서로 다른 모델의 예측 확률 결합 | 모델별 오류 패턴 보완 |
| **② 가중치 비교** | 균등 평균과 가중 평균 비교 | 모델별 기여도 확인 |
| **③ 실험 조건 통일** | seed·epoch·확률 보정·예측 파일 규격 확인 | 신뢰할 수 있는 비교 |
| **④ 형제 모델 분석** | 혼동이 많은 모델 쌍의 예측 확률과 문체 차이 분석 | 같은 개발사 내부 모델 구분 개선 |

### 검증할 질문

- 서로 다른 모델의 오류는 얼마나 겹치는가?
- 단일 모델보다 앙상블이 val 성능을 높이는가?
- 가중치 조정이 성능 개선에 도움이 되는가?
- 같은 개발사의 형제 모델을 더 잘 구분할 수 있는가?

> [!NOTE]
> **팀 통합 앙상블은 향후 검증 계획입니다.**
>
> - 팀원들의 val·test 예측 파일과 실험 조건을 확인한 뒤 진행합니다.
> - 조합 후보와 선택 기준은 팀 합의에 따라 결정합니다.
> - 최종 조합은 val 성능으로 정하고, test는 공식 평가 단계에서 사용합니다.
> - 실제 개선 여부는 검증 이후에 판단하며, 기대 효과를 확정된 결과로 표현하지 않습니다.

> [!TIP]
> **🎙️ 말할 것**
>
> "지금까지는 각 모델의 특징과 개선 효과를 확인했습니다. 앞으로는 서로 다른 모델이 틀리는 패턴을 분석하고 예측을 결합해, 특히 형제 모델을 더 잘 구분할 수 있는지 확인할 계획입니다."
